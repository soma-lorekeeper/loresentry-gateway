# Access Token과 사용자 신원 검증

> 이전 구현의 실행 기록이다. 2026-09-26 단일 세션 ID 설계의 구현·검증 완료 근거로 사용하지 않는다. 당시 결과와 수치는 보존한다.

2026-09-24, LOREKEEPER-561. 임시 X-User-Id 인증을 제거했다. 보호 요청은 쿠키 AT의
RS256 서명과 등록 kid, iss·aud·token_type·sub·jti·sid·iat·exp를 확인한다.
sid는 UUID v4이며 미래 iat와 만료에 30초 시계 오차를 적용한다. 만료 외 검증을
먼저 수행해 잘못된 토큰을 재발급 가능한 만료 오류로 분류하지 않는다.

Java 21 `./gradlew --no-daemon build` 성공: 135개 테스트, 실패·오류·생략 0개.
실제 RSA 서명으로 다른 키·RS512·등록되지 않은 kid·누락/잘못된 클레임·시간 경계를 검증했다.
공개키 파일은 기동 시 읽고 누락·잘못된 PEM·개인키 형식·2048비트 미만 RSA를 거절한다.
JWT의 URL로 키를 조회하지 않는다. 테스트 개인키는 메모리에서만 생성하며 저장소에는
기동 테스트용 공개키만 포함한다.

MockMvc 실제 검증 필터에서 외부 사용자 헤더만으로는 컨트롤러에 도달하지 못했다.
유효한 AT의 sub는 외부 헤더의 값·대소문자·중복에 영향을 받지 않았고, 후속 요청에서
외부 사용자 헤더를 제거했다. 일반 보호 요청은 RT 없이 동작하며 정확한 OAuth GET 및
refresh/revoke POST만 AT 검사 없이 각 인증 흐름에 진입한다.

이번 Atomic은 AT 검증까지다. 현재 로그인 세션 조회는 다음 LOREKEEPER-562에서
연결하며, 이 중간 커밋만으로 최종 인증 구현 완료나 배포 가능 상태를 주장하지 않는다.
