# Auth·BFF 단일 세션 전환 인계

**코드 통합 완료와 운영 전환 완료를 구분한다.** 2026-09-24 격리 통합 검증은 통과했고,
프론트 의존 검증은 사용자 승인으로 이번 범위에서 제외했다. 운영 GitOps·자격 증명·접근
제한 준비는 미완료다. [운영 준비 목록](OPERATIONS.md)의 증거가 확보되기 전에는 main
push·자동 배포를 실행하지 않는다.

기준은 [Auth 단일 세션 설계](../../loresentry-authentication/docs/token/SINGLE_SESSION_DESIGN.md)다.
이 문서는 수행할 절차이며 아래 운영 작업을 실행했다는 기록이 아니다.

## 전환 전 준비

1. Auth와 BFF가 동일한 JWT 공개키·kid, sid 계약과 세션 저장소를 사용하도록 준비한다.
   BFF는 개인키 없이 공개키만 읽고, 세션 쓰기 담당 노드에 전용 GET 계정으로 연결한다.
2. GitOps의 prod 프로필·Secret 참조·공개키 마운트·접속 설정을 검토한다. CNI의
   NetworkPolicy 집행과 Auth·Content 우회 차단, Redis BFF ACL을 실제 환경에서 검증한다.
3. [실제 서비스 검증 도구](../integration/session/README.md)를 대상 커밋으로 실행한다.
   환경별 Google callback·브라우저 Origin·HTTPS 쿠키 설정과 인증 오류 관측을 준비한다.
4. 프론트는 쿠키·CSRF·result/users/me·명시적 재발급·탭 조율 계약을 구현해야 한다.
   이번 브라우저 검증 제외 승인이 실제 프론트 호환성이나 사용자 로그인 가능성을 보증하지
   않는다. 미준비 프론트가 접근하는 동안 임시 X-User-Id 요청은 새 BFF에서 거절된다.

## 공동 전환

1. 전환 시간과 재로그인 영향을 알리고 인증·보호 API 트래픽을 제어한다. 구 인스턴스의
   진행 요청을 배출한다. 이미 인증된 요청 취소나 열린 스트림 강제 종료를 BFF 세션 조회가
   보장하는 것으로 간주하지 않는다.
2. Auth와 BFF를 새 계약으로 교체하고 구 인스턴스를 제거한다. Auth만 새 sid를 발급하거나
   BFF 일부가 세션 조회를 생략하는 혼재 상태는 완료로 인정하지 않는다.
3. sid 없는 기존 AT·RT가 거절되는지 확인한다. 새 로그인, 다른 로그인에 의한 세션 교체,
   같은 sid 재발급, 이전 세션 로그아웃의 새 세션 보호와 현재 로그아웃을 확인한다.
4. 각 BFF 인스턴스에서 Redis 장애의 503·쿠키 미변경·내부 호출 차단을 확인하고,
   준비된 프론트에서 재발급 반복과 늦은 응답 덮어쓰기가 없는지 확인한 뒤 트래픽을 재개한다.

기존 토큰은 자동 승계하지 않고 재로그인을 요구한다. `auth:refresh:*` 키는 TTL로 정리하고
새 코드의 fallback으로 읽지 않는다. 전환 목적으로 Redis 전체를 flush하지 않는다.
무중단 전환이나 기존 로그인 유지가 보장되는 절차가 아니다.

## 롤백·복구

이미지 태그만 이전 버전으로 돌리기 전에 Auth·BFF 계약을 함께 확인한다. 구 키가 남아 있고
같은 서명키를 사용하면 구버전이 폐기된 이전 로그인을 다시 허용할 수 있다. 트래픽을 제어한
상태에서 범위를 제한한 이전 키 폐기나 서명키 교체 등 재인증 방안을 확정한 뒤 복구한다.
구 세션 검사를 우회하는 fallback을 임시로 추가하지 않는다.

저장소 유실은 재로그인으로 처리한다. 과거 스냅샷을 활성 세션으로 무조건 재사용하면
로그아웃·세션 교체가 취소되는 효과가 생길 수 있으므로, 복구 자료의 시점과 재인증 범위를
인프라 담당자가 검증해야 한다. 운영 변경·rollback·키 폐기는 별도 실행 범위다.

## 현재 인계 상태

| 범위 | 결과 |
| --- | --- |
| BFF 구조·보안·Auth API | 구현 및 일반 테스트 204개 통과 |
| 실제 Redis·Valkey | 10개 드라이버·ACL·세션 회귀 통과 |
| 실제 Auth·BFF 두 인스턴스·Content | 로그인 수명주기·장애 및 기존 Content 26개 API 회귀 통과 |
| 프론트·브라우저 | 미구현·미검증; [사용자 승인에 따른 제외 기록](verification/LOREKEEPER-574.md) |
| 운영 설정·NetworkPolicy·ACL | [운영 준비 미완료](OPERATIONS.md); 실제 클러스터 적용·검증 안 함 |
| main push·운영 배포 | 전체 로컬 통합 후에도 운영 준비가 충족될 때까지 보류 |

과거 이슈별 테스트 기록은 해당 실행 시점의 결과로 유지한다. 새 구현이 과거 검증에서
통과한 것처럼 수치·결론을 소급해 바꾸지 않는다.
