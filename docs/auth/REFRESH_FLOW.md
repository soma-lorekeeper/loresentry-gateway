# BFF 토큰 재발급 연동

**재발급은 프론트가 명시적으로 요청한다.** BFF는 일반 API 요청 처리 중 자동으로
재발급하지 않는다. RT 상태 변경은 Auth가 수행하며, BFF는 일반 보호 요청에서만 공유
활성 세션을 읽기 전용으로 조회한다.

1. BFF는 보호 API의 AT가 만료됐거나 없으면 내부 서비스로 전달하기 전에 요청을 거절한다.
   프론트가 재발급 가능한 상황을 구분하도록 `401`과 오류 코드를 반환한다.
2. 프론트는 BFF의 재발급 API를 호출한다. 동시에 실패한 다른 요청은 같은 재발급 결과를
   기다리며, 같은 브라우저의 여러 탭 사이에서도 재발급 요청이 겹치지 않도록 조율한다.
3. BFF는 CSRF를 검증하고 쿠키의 RT를 Auth에 전달한다. 성공하면 새 AT·RT로 쿠키를 교체한다.
   프론트는 HttpOnly 쿠키의 토큰을 직접 읽거나 저장하지 않는다.
4. 프론트는 재발급 성공 후 거절됐던 원래 요청을 한 번만 다시 보낸다.
   재발급 API 자체에는 이 자동 재시도 흐름을 적용하지 않는다.

원래 요청의 재시도는 내부 전달 전 AT 만료·부재로 거절한 경우에 한정하며 모든 `401`·네트워크 오류에 적용하지 않는다.
탭 간 잠금·완료 확인과 늦게 도착한 오류의 조율은 [프론트 재발급 메모](../../../docs/frontend/TOKEN_REFRESH.md)를 따른다.

실패 시 쿠키와 RT 소비 여부 처리는 [외부 재발급 응답](../EXTERNAL_API.md#재발급-응답)을 따른다.
AT가 만료됐거나 없어도 재발급 경로에 접근할 수 있어야 한다.

정상 재발급은 sid를 유지하므로 이전의 미만료 AT도 활성 세션 검사에 통과한다.
SESSION_INVALID·SESSION_UNAVAILABLE와 내부 서비스의 401은 재발급 대상으로 사용하지 않는다.
실제 BFF·Auth 검증 결과는 [단일 세션 통합 기록](../verification/LOREKEEPER-573.md)에 있다.
